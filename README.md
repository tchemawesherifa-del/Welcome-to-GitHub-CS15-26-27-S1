# Welcome to GitHub


When you click a link to open a new GitHub assignment, it will take you to a GitHub **repository**. A repository is a collection of files (usually code files) that have been added to GitHub. Repositories also track changes over time. 

Below is a basic example of a repository.

![Example of a GitHub repository.](images/example-github-repo.png)

This repository is intended to show you the basic steps required for **forking**, **cloning**, **modifying**, **saving**, **committing**, and **pushing** a repository. In Computer Science, this will be how you start and submit assignments!

The following steps will apply to **every single assignment** you do in Computer Science, so don't be afraid to return back to this for instructions down the line.

## 1. Open the assignment repository

Start by clicking on the link for the assignment, probably provided through Schoology. This will bring you to the assignment repository.

![Example of a GitHub repository.](images/example-github-repo.png)

## 2. Click Fork in the top-right corner of the repository

Forking a repository creates a new copy of it. The copy is still connected to the original. If the original repository is changed, the forked copy can be synced to the original. However, if a forked repository is modified, the original cannot sync its changes.

![An image showing where the "fork" button is located on the GitHub Website](images/click-fork.png)

## 3. Select your personal GitHub account as the owner, then click Create fork

Choose yourself as the owner of the repository. Then create the fork. 

*Please do not change the repository name.*

![The sub menu that opens when forking a repository.](images/fork-options.png)

If you forked it correctly, a new repository should pop up with your GitHub account where these 3 dots are.

![An image showing what a successful fork should look like.](images/successful-fork.png)

## 4. In your new fork, click Code, then select Open with GitHub Desktop

This creates a clone of your repository. A clone isn't a separate copy like a fork is. Instead, it's just a new instance of the repository. All clones sync with one another from the same repository.

Cloning through GitHub Desktop is the easiest way to do it right.

![An image showing how to clone the repository with GitHub desktop](images/clone-with-desktop.png)

## 5. In GitHub Desktop, choose where to save the project and click Clone

GitHub Desktop will then open with this dialogue box. Click "Clone". 

Optionally, you can choose where to save your repository. Once it is placed somewhere, you can't move it or else GitHub Desktop will lose it and no longer be able to access it.

![Showing where the clone button is when GitHub Desktop Opens](images/clone-dialogue.png)

## 6. Be sure to clone the project for your own purposes

By default, GitHub Desktop will have "To contribute to the parent project" selected.

**YOU DO NOT WANT THIS!**

Make sure you select "For my own purposes" before continuing, or you will likely run into issues when trying to submit your assignments.

![Ensure that you clone for your own purposes](images/own-purposes.png)

## 7. Open your repository in PyCharm

You may need to set PyCharm as your default code editor for GitHub Desktop. This can be done by going into the "Options" and selecting "JetBrains PyCharm".

![Open the editor settings](images/open-editor-settings.png)

![Set the default editor to PyCharm](images/set-editor-pycharm.png)

Once PyCharm is your default editor, you can open repositories directly in PyCharm!

![Opening a repository in PyCharm from GitHub Desktop](images/open-in-pycharm.png)

## 8. Make some changes and modify the repository 

With PyCharm open, you can see your **File Explorer**.

![The location of the PyCharm file explorer](images/file-explorer.png)

From the File Explorer you can open and modify files. We will modify this tutorial by opening it in edit mode.

![Opening a markdown file in edit mode.](images/open-md-in-edit-mode.png)

Type something into the `README.md` file (it can be anything you want as long as it is school appropriate).

*(Also, the read me in the picture has less text in it, that's okay. You can still type in the `README.md`).*

## 9. Save your changes

PyCharm automatically saves files pretty frequently, but it's better to be safe than sorry. 

![Saving all in PyCharm](images/save-all.png)

## 10. Open GitHub Desktop and review the files you changed

GitHub Desktop has 3 main panels after you have made changes in a repository:

### A

This section lists the files that were changed. 

* A yellow dot means a file was changed.
* A green `+` means that a new file was added
* A red `-` means a file was removed (or moved to a new folder)

### B

This section shows exactly what parts of a file were changed. It goes through line by line and highlights sections that were added or removed.

### C

This section is where you confirm the changes. It includes a space for you to note what changes where made.

![Different sections of reveiwed changes](images/review-changes.png)

## 11. Enter a short description of your changes, then click Commit to main

Before you can commit, you **must** write a summary.

You also **may** write a commit message. I recommend always including a commit message because it helps keep track of what changes have been made from edit to edit.

Then you Commit the changes. Commiting the changes updated the repository to start tracking from a new point. It's like a checkpoint in time, and at any time down the line, you can restore a project to a previous commit.

![Shows where to write the commit summary and commit message](images/commit-to-git.png)

## 12. Click Push origin to upload your committed changes to GitHub

Once changes have been committed, this only updates the repository on your computer. To update the changes on GitHub, you need to Push the changes.

Push origin is how I can see your updated code! Make sure you push often!

![Push the commited changes to GitHub](images/push-to-github.png)

## 13. Check your repository on GitHub to confirm that your changes were uploaded

By clicking "View on GitHub" you can see the changes you made on the GitHub website! This is a great way to verify that your changes were successful.

![The button to view your repository on GitHub](images/view-on-github.png)

![A changed repository on GitHub](images/changed-repo-github.png)

## 14. Submit the link to your repository on Schoology

Finally, copy the link from your GitHub and submit it to Schoology.

Please ensure you actually make it a link instead of just text!
